# 单段分段执行客户端 r2

**用途：在现场已确认的受控、静态工位中，只提交一段臂手目标。** 本版采用固定的“停稳观测—等待预测—复核反馈—现场确认—执行一段—退出”流程，不是无限循环或连续实时控制程序，也不是抓取成功保证。

**请完整使用 r2 包，不混用上一版入口或适配器。** 运行报告中的 `client_revision` 应为 `stationary-single-segment-r2`。服务地址、Token、任务和到期时间不变。

## 1. 与原程序的区别

原程序把 16 个目标安排在开始读取观测后的约 0.8 秒内；如果结果到达较晚，整段就被丢弃。

本版不会把等待期间当成动作已经执行。等待时不提交轨迹，持续核对实际臂手反馈；结果返回后，再核对反馈并由现场操作者确认工件和工位未改变，才建立本段执行时间轴。**这是分段执行模式，不是关闭所有过期检查，也不是把旧观测时间改成新时间。**

- 总试用预算 **120 秒**，从首次现场确认后起算；达到预算不再开始新请求或提交新目标。
- 最多 **一次预测、一个 16 目标的动作段**，目标间隔仍为 50ms。初始化的当前位置保持指令不属于新的预测段。
- r2 在预定发送时刻**之前**读取反馈并计算目标，不再先等到发送时刻才开始读取。50ms 间隔和 20ms 迟到容差不变。
- 手部按现有适配条件以 100ms 间隔提交该段中的对应目标；保留中指，仅后两维固定零。
- 段末只短时保持最后实际提交的臂目标，核对反馈后再停止：最多 2 秒、计入 120 秒预算，不增加预测段、不生成新的目标位置。
- 默认三指。程序没有自动重复、重新推理补救、上电、清除故障、归位或断电逻辑。
- 这不是让机械臂运行 120 秒。段间等待是本模式的特征；完成当前段后即退出，不自动执行下一段。

## 2. 现场前提

首次使用须由现场控制工程师确认以下条件；不能只凭远端 `ready=true` 判断：

1. 实际臂关节、手指通道、单位、方向和零位与现有适配器一致。
2. 控制器自身的限位、急停、保持与停止行为已经验证；工作范围内无人、无碰撞障碍，首次试用有人监护。
3. 其他执行程序已经按现场安全流程停用，控制器处于现场确认的可保持状态，并已由现场安排适合任务的起始姿态。程序不把关节全零或某组手指 raw 值当作通用初始姿态。**本程序不会替现场使能或解除故障。**
4. 等待期间工件、夹具、机械臂和手的状态不能被外部改变；程序只检查关节反馈，不能自动证明场景未变化。
5. 使用客户现有、已能运行驱动的 Linux Python 环境和厂商 SDK。不得为试用随意升级系统、驱动或设备固件。

程序沿用已有客户程序的软件调度限制，并增加等待反馈门槛：

| 项目 | 固定软件值 |
| --- | --- |
| 臂目标相邻变化限制 | 每 50ms、每关节最多 0.04rad |
| 臂反馈跟踪误差上限 | 0.2rad |
| 手目标相邻变化限制 | 每 100ms、每通道最多 6 raw |
| 等待阶段臂反馈变化容差 | 相对原观测最多 0.02rad |
| 等待阶段手反馈变化容差 | 相对原观测最多 5 raw |
| 调度迟到容差 | 20ms；超过时停止新目标，不跳过后继续追赶 |
| 最后臂目标的完成核对 | 相对最后实际提交的目标，反馈连续 5 次在 0.02rad 内；最多保持 2 秒 |

**这些数值不是硬件安全认证，不能代替实际关节限位、工作空间保护或现场风险评估。** 现场工程师需确认它们适用于本设备；不适用时不要通过改大数值绕过检查。raw 零位不代表张开或安全姿态。

## 3. 文件与配置

将本包解压到新的独立目录，保留现用程序。包内提供本入口、配套 HTTPS SDK、适配器工作副本、启动脚本、公开会话信息及依赖清单；不包含 Token、厂商二进制、客户观测或完整设备 SDK。

继续使用原 `config-v2.toml` 的完整路径。相对 Token／NRC SDK 路径仍按该配置文件所在目录解析。不要把 Token 复制进本包，也不要把客户原始压缩包作为本次交付附件。

- 地址：`https://festival-usd-payday-surveys.trycloudflare.com`
- 接口：`customer-api-v2`，三路原始 RGB `640×480`，12 维实测状态、`16×12` 目标。
- 默认三指，保留真实中指反馈与目标，仅索引 10、11 固定零。
- 原 Token 继续使用，**固定到期为北京时间 2026-10-29 11:15:26**；首次运行不重新计时。

相机副本增加了严格原图检查，并采用同步读取；错误尺寸／类型会报错，不裁剪、补边或放大小图。臂手适配不重写关节单位和通道映射。现场已有的厂商库仍从原配置路径加载，其初始化和设备超时行为必须由现场确认。

## 4. 固定试用流程

在客户已有的驱动环境中运行包内入口，配置参数指向现有文件：

```text
bash run_stationary_client.sh --config "<现有config-v2.toml完整路径>" --report stationary-result.json
```

启动脚本使用当前 `python`；如现场原环境使用独立解释器，可通过 `PYTHON_BIN` 指向同一解释器。不要临时换环境安装一套不同版本的设备驱动。包内 `requirements.txt` 只列 HTTPS SDK 依赖，不代替现场驱动安装。

程序会停下来要求两次本地确认：

1. **现场条件确认**：确认上述前提后按屏幕提示输入。随后开始 120 秒预算，检查状态、取得观测并请求一次预测。若状态不符合要求，程序停止，不自动上电或回零。
2. **本段确认**：预测回来后，确认工件、夹具和工作空间仍未改变，再按屏幕提示输入。输入期间继续核对关节反馈；状态改变、超预算或取消都不提交本段。

程序只接受交互式终端确认，不接受管道自动回答。不要去修改原程序的运动开关、过期阈值或回包字段来代替本流程。

同一配置目录下的本客户端会使用本地互斥锁，防止误开两个实例；它不能锁住客户其他控制软件，其他执行程序仍必须由现场停用。

通过检查后，程序才打开本次 ServoJ 通道、保持当前臂位置并提交一段目标。正常结束时，先确认最后实际提交的臂目标已在软件反馈容差内，再关闭通道；期间可能重复发送同一个保持目标，这不是第二段预测。异常时停止新增目标并尝试结束通道，不为了等待手部阻塞调用而推迟停止机械臂，**不返回全零位置、不重置手姿、不自动断电，也不开始下一轮**。

运动前和运动中仍要求控制器处于已确认的运行状态。正常关闭 ServoJ 后进入 Ready 状态，不再被误报为“未准备好”；若控制器报告故障，仍停止并保留故障，不自动清除。

模型若给出保持当前位置的目标，设备可能没有明显位移；程序不会为了“看起来动了”制造额外动作。

## 5. 异常与结果

| 输出／报告情况 | 含义与处理 |
| --- | --- |
| `controller_not_ready...` | 控制器状态不符合现场确认条件；联系现场工程师，不让程序自动解除故障 |
| `arm_moved_while_waiting`／`hand_moved_while_waiting` | 反馈相对观测发生变化，本次计划不再使用 |
| 图像、状态、固定通道或预测范围错误 | 停止并核对实际适配，不伪造反馈或随意改图像 |
| `request_timeout`、鉴权或服务到期 | 没有可执行的本次结果，不自动重试或用旧结果替代 |
| `actuator_schedule_missed`／`hand_submission_failed`／跟踪超限 | 停止提交后续目标，按现场已验证的停止与接管流程处置 |
| `final_arm_target_not_settled` | 保持期间反馈仍未达到最后实际提交的臂目标容差；不能把“已发送”当作“已完成” |
| `cleanup_failed` | 结束／释放资源发生错误；报告保留错误及此前结果，不将本轮显示为无异常完成 |
| `single_segment_submitted` | 一段命令调用及最后臂目标的软件反馈核对已完成；**不等于抓稳、无碰撞、完整任务成功或实机验收通过** |

厂商驱动若阻塞或通信故障，软件无法保证瞬时停止设备。120 秒是程序停止新增请求／目标的预算，不代替驱动超时和物理急停；已经提交的目标如何停止，由现场已确认的控制器行为决定。不要靠再次启动程序来“补完”失败段。

保留生成的 `stationary-result.json`。其中区分调用尝试、成功返回、观测年龄、反馈变化和失败阶段，不保存原始图像、状态数组、目标数组或凭据。`arm_targets_submitted` 是预测段中的目标数，`arm_hold_targets_submitted` 是重复最后目标的保持调用数；完成核对针对限幅后实际提交的臂目标，不冒充原始预测准确率。

r2 另记录反馈读取最大耗时、目标调用最大耗时和首次发现的调度迟到，便于区分通信耗时与真正的控制周期不足。若失败，先保存报告，不自动重复；后续试用须重新确认现场条件及有限范围。等待预测时若检测到姿态变化，会取消后续尚未发出的预测操作；已经在途的请求可能返回，但其结果不会用于运动，也不会为凑次数再请求。

## 6. 数据与许可

本次临时 HTTPS 通道由 Cloudflare 转发，TLS 在其边缘终止，图像和状态会经过该第三方处理；只上传已获授权的数据。Token 保留于原私有位置，不写入源码、命令参数、日志或普通压缩包。保留客户源文件及第三方依赖依法随附的许可声明。
