# 客户端 v2 修改要求

适用对象：现有 CR3/O6 客户程序。请结合本次 `customer-integration-kit-20261026.zip` 完成修改；包内提供 v2 SDK、依赖清单、完整接入说明、实际配置快照及会话信息。

**本说明是代码修改与核对清单，不是设备运行指令。预测接口已经通过真实观测请求验证，但现场执行、手指物理映射、连续控制和抓取效果仍需分别验收。**

## 1. 接入地址、SDK 和加载路径

| 项目 | 本次要求 |
| --- | --- |
| 服务地址 | `https://festival-usd-payday-surveys.trycloudflare.com`，公网 TCP 443、HTTPS/JSON |
| 接口 | `customer-api-v2`，使用 `/v2/metadata`、`/v2/infer`、`/v2/reset`；旧 `/v1` 不兼容 |
| 凭据 | 原客户 Token 继续使用，保留原私有凭据文件及其读取路径 |
| 期限 | 北京时间 **2026-10-26 11:15:26 至 2026-10-29 11:15:26**；从实际启动起 72 小时，更新客户端或首次调用不重新计时 |

请修改以下位置：

1. **`config.toml` 的 `[customer].api_url`**：改为上述域名，不附加 `/v2`。`token_file` 继续指向既有私有 Token 文件。使用环境变量的部署方式相应更新 `CUSTOMER_API_URL`，保留 `CUSTOMER_API_TOKEN_FILE`。
2. **SDK**：使用本次包内完整的 `scripts/customer_client.py`，依赖按包内清单安装，Python 使用 3.11 或以上。不要只改旧 SDK 的版本字符串、任务常量或 README。
3. **`deploy_cr3_o6_customer.py` 的 `CUSTOMER_CLIENT_PATH`**：确保实际加载的是新 SDK，而不是旧包目录中的同名文件。例如，将新包解压到客户项目下的 `customer-integration-kit-20261026` 目录后，路径为：

```python
CUSTOMER_CLIENT_PATH = (
    SCRIPT_DIR / "customer-integration-kit-20261026" / "scripts" / "customer_client.py"
)
```

这是 SDK 路径配置，不是启动命令。原 Token 不随新包复制或重新打包；若原路径位于旧目录，升级时也不要误删该凭据文件。新域名须加入客户网络所需的 DNS／出站 TCP 443 白名单。

## 2. 图像采集与输入检查

| 客户代码位置 | 修改要求 |
| --- | --- |
| `cr3_o6_camera.py`：`CR3O6CameraInterface` | 采集原始宽 640、高 480 的 RGB 图像；输出宽高也应为 640、480，不再使用 224、224 |
| 同文件：`_read_one()` | 移除上传前的 224 方图缩放、黑边填充和裁剪；原始尺寸不符时明确报错，不把旧小图放大冒充原始图像 |
| `deploy_cr3_o6_customer.py`：`_read_observation()` | 图像检查改为 RGB、`uint8`、形状 **`(480, 640, 3)`**，注意数组顺序为高、宽、通道 |
| 同文件：`_check_metadata()` | `image_shape` 核对为 `[480, 640, 3]`，与 SDK 和实际输入一致 |

相机键仍严格为 `top`、`wrist`、`side`。现有配置分别对应 `base_0_rgb`、`left_wrist_0_rgb`、`right_wrist_0_rgb`，请核对物理机位，不因名称带 wrist 就交换侧面和腕部相机。若采集库返回 BGR，应明确转换为 RGB。

客户端上传原始图像，服务内部按最短边 384、保留完整视野处理；客户端不要预先缩到 384。SDK 使用 PNG 无损编码：单张 PNG 不超过 **1 MiB**，完整 HTTP 请求体不超过 **5 MiB**。

## 3. 状态、手指目标与校验范围

状态仍为 `(12,)`，动作仍为 `(16, 12)`，不增加维度。变化在于中指成为可变通道：

| 索引（从 0 开始） | 含义与要求 |
| --- | --- |
| 0–5 | 六个臂关节；输入为实测位置，输出为绝对关节目标，单位 rad，不是增量 |
| 6、7 | 拇指弯曲、拇指侧向；原始设备刻度 |
| 8 | 食指；原始设备刻度 |
| **9** | **中指，保留真实反馈与预测目标，不再固定为零** |
| 10、11 | 无名指、小指，接口约定固定零 |

**三指对应四个可变手部通道：拇指占两维，食指、中指各一维。不能把“前三个手部数值”理解为“三根手指”。**

需要联动修改：

- **`_read_observation()`**：移除 `state[9:] = 0.0`，保留读取到的真实中指反馈。第 10、11 通道也不能为了通过校验而伪造；若实测不符合固定零约定，应停止本次调用并核对设备映射。
- **`_live_hand_commands()`**：当前只取 `action[6:9]` 并补三个零，会丢掉中指。目标构造必须包含索引 9，并按确认后的物理通道顺序处理完整六维手部目标，不能继续把中指覆盖为零。
- **`_execute_live_chunk()`**：手部可变目标检查范围应包括 `actions[:, 6:10]`；固定通道检查从 `actions[:, 9:]` 改为 `actions[:, 10:]`。手部漂移／反馈比较也应由前三维扩展到前四维，即实测手部 `[:4]` 对应观测 `state[6:10]`。
- **`_check_metadata()`**：`fixed_zero_channels` 改为 `[10, 11]`；状态／动作名称、形状、单位和时间间隔仍须完整核对。
- **`cr3_o6_interface.py` 与 O6 适配层**：核对实际返回顺序、零位、方向和目标／反馈刻度。臂只在设备边界完成一次 rad／degree 转换；手部不额外归一化或转换成角度。

raw 零值不等于角度零、张开或安全姿态。选择两指任务时也要上传真实中指反馈，不按任务名称将反馈或返回目标硬改为零。

## 4. 三指任务怎样选择

**新版 SDK 默认三指。** 升级正确后，原来的调用可以保留：

```python
actions, info = customer.infer(images, state)
```

对应的完整任务文本是：

> Use the thumb, index finger, and middle finger to pick up the motor and place it on the right side with the protruding side facing left. Keep the ring and little fingers at their recorded zero positions.

如果客户程序另有显式任务字符串，应改用新版 SDK 的 `TASKS["three_finger"]`。独立轮次需要两指时，使用 `TASKS["two_finger"]`；也可从实际配置的 `supported_tasks` 字典取得对应完整文本，再通过 `task=` 传入调用。

`"three_finger"`／`"two_finger"` 是字典键，不是 HTTP `task` 接受的简写。不要沿用旧任务字符串、翻译或自行改写文本。响应中的 `info["task"]` 应与所选完整文本一致；任务回显不代表设备已切换抓法，也不提供运动中的安全抓法切换保证。

这些职责字段不是现场使能开关，`ready=true` 也不是运动许可；不要删除本地许可、限位、互锁、急停或人工接管措施。

## 6. 执行时序与回零：不能随接口升级自动认定可用

**本次公网高清请求记录耗时约 1.10–4.50 秒，已超过 16 步约 0.8 秒的名义覆盖时间。** 这是接口验收环境的有限观测，不含客户现场采集，不代表客户网络表现；目前未通过连续实时执行验收。

- 不要通过调大 `LIVE_MAX_OBSERVATION_AGE_S` 或请求超时来接受更旧的动作，也不能在收包后从第一个动作重新计时播放整段。
- 分开记录观测采集、请求返回、实际下发和反馈时间，使用一致的时基。分别保留原始预测、客户端处理后的目标及实测反馈，核对动作年龄和臂手配合。
- 当前手部按 `actions[::2]` 降为 10Hz，有限幅、取整及可能跳过迟到目标的处理。这些处理不等同原始预测轨迹，不能未经验证就沿用为三指执行方案；也不能仅为追齐速度而去掉保护限制。
- 审查现有初始手姿、启动归位、任务结束及异常回零逻辑。网络失败不等于需要回零；原两指初态不能直接视为三指初态，不能凭任务名称猜新的数值。
- 故障按现场已验证的保持／受控停止和接管流程处理，不把全零目标当通用安全停止。`customer.reset()` 只重置预测侧状态，不是设备回零或清除控制器队列。
